# Graffle

*Leer en [español](README.es.md).*

A native macOS diagramming and vector drawing app (Swift + AppKit), inspired by OmniGraffle.

## Build and run

```bash
./scripts/bundle.sh        # builds build/Graffle.app
open build/Graffle.app
```

Requires only the Command Line Tools (or Xcode) and macOS 13+. `swift run` also works.

### Installer (.dmg)

```bash
./scripts/make-dmg.sh      # builds build/Graffle-<version>.dmg and its .sha256
```

Opening the DMG shows a window with the app, a shortcut to *Applications* and a background telling you to drag one onto the other; the volume carries the Graffle icon. The script builds the app, assembles the image, applies the window layout through Finder (if macOS doesn't grant Finder Automation access, the DMG is still produced, just without the custom window), compresses it and **mounts it to verify it** (signed app, link to Applications, background, volume icon and layout). The app is ad-hoc signed and not notarized: on another Mac, the first time you have to open it with right-click → Open.

## What's included

- **Multiple documents:** open as many diagrams as you like, each in its own window with its own canvas, inspector, palette, undo history and "edited" state. File → New opens another; Open… and Open Recent open `.graf` files (also by double-clicking in Finder or dragging onto the Dock; opening a file that is already open brings its window forward instead of duplicating it). Save, Save As and Revert to Saved; closing a window (or quitting) with unsaved changes asks Save / Don’t Save / Cancel. `.svg` files also open as a new, unsaved diagram named after the file. Windows follow the system setting *Prefer tabs when opening documents*; the Window menu has Show Tab Bar, Merge All Windows and Move Tab to New Window.

- **Quick Look preview:** select a `.graf` file in Finder and press the space bar to see the diagram (a sharp, vector preview, sized to the diagram; an empty diagram shows a note). It is a Quick Look extension inside the app (`GraffleQuickLook.appex`), so it works in Finder, Spotlight and anywhere else macOS previews files. macOS registers it when the app is installed in `/Applications` (or opened from where it is); if the preview doesn't appear straight away, run `qlmanage -r` and check that *Graffle Quick Look* is on in System Settings → General → Login Items & Extensions → Quick Look.
- **Architecture diagrams from code:** *File → Import Project Architecture…* analyzes an Xcode workspace (`.xcworkspace`), project (`.xcodeproj`), Swift package (`Package.swift`), **.NET solution** (`.sln`, `.slnx`) or project (`.csproj`, `.fsproj`, `.vbproj`), **Android / Gradle build** (`settings.gradle(.kts)`), or a folder containing one, and opens a new, unsaved diagram of its modules. Every target is a node (apps, extensions, frameworks, libraries, tools, tests) with its platform, languages and file count; edges are target dependencies, links and embeds (dashed orange), and Swift package uses (purple, with the resolved version from `Package.resolved`). Local packages and referenced projects are followed. The layout is layered — dependents on top, what they depend on below — and dependency cycles are drawn as red dashed connectors labeled "cycle". Choose whether to include system frameworks, test targets and external packages in the open panel. Everything is a normal, editable Graffle drawing (layers: Dependencies, Targets, Packages, System, Legend). For .NET, every project is a node (web app, application, library or tests, with its target frameworks, language and file count); edges are `ProjectReference`s, NuGet packages (versions from the project or `Directory.Packages.props`) and shared frameworks (`FrameworkReference`); referenced projects outside the solution are followed. External packages and system frameworks get their own rows at the bottom. For Android and other Gradle builds every module from `settings.gradle(.kts)` is a node (Android app, library, dynamic feature, JVM library, multiplatform, with `minSdk`, Kotlin/Java and file count); edges are `project(":x")` and `projects.x` dependencies and external libraries (coordinates and versions from the build file or `gradle/libs.versions.toml`). Test configurations and commented-out lines are ignored, and Gradle itself is never run. Projects are read from `project.pbxproj` directly (no Xcode or build needed); packages use `swift package dump-package`, so the Command Line Tools must be installed.
- **Ready-made diagram types:** besides Blank, Software Architecture and Classes, the New Document wizard offers starters to edit: **UML Diagram** (classes with inheritance, an interface and associations), **Entity-Relationship Diagram** (tables with zebra-striped fields joined by crow's-foot relationships), **Conceptual Diagram** (a central concept, linked concepts and linking phrases), **Synoptic Diagram** (a general idea broken down with braces), **Pyramid Diagram** (stacked levels with labels), **Ishikawa Diagram** (fishbone with six cause categories) and **Tree Diagram** (a decision tree with labelled branches). **Circuit Diagram** (an electronic schematic starter; drawing only, nothing is simulated). The **Circuit** menu is a parts bin with 29 symbols — sources, ground, resistor, potentiometer, capacitors, inductor, fuse, diode, Zener, LED, NPN/PNP transistors, switch, lamp, voltmeter, ammeter, motor, op-amp, AND/OR/NOT/NAND/NOR/XOR gates and junction — each with a thumbnail; a symbol lands in the middle of the view labelled R1, C2… in order. Symbols are single path shapes with *pins* at the ends of their leads: connectors (set to Orthogonal) snap to the pin that faces them, with a single corner between horizontal and vertical leads, also after *Arrange → Rotate Clockwise/Counterclockwise* (⌥⌘R / ⇧⌥⌘R). Everything is ordinary shapes, connectors and text you can restyle, and every theme applies (lines and braces take the theme's connector look). Connectors have new entity-relationship ends — *Many*, *One or Many*, *Zero or Many*, *Exactly One* and *Zero or One* — in the Start/End menus, drawn on the canvas, PNG, PDF and SVG.
- **Shape Library:** a second, collapsible sidebar (toolbar button next to the sidebar toggle, *View → Show Shape Library*, ⌃⌘L; it remembers whether it was open and folds away by itself in narrow windows). It holds 100+ ready-made shapes in collapsible categories — Basic Shapes, Polygons and Stars (regular 5–12-sided polygons, 4–12-point stars, burst), Arrows, Flowchart, Callouts and Notes, Diagram Parts (actor, package, server…) and all the Circuit Symbols — each with a thumbnail, with a search box that also understands synonyms ("start" finds Terminator). Click a shape to put it in the middle of the view or drag it to an exact spot; it takes the current default style and the document's theme and can be undone like anything else. **My Shapes:** select any objects (connectors between them come along), press **+** in the library header and name them; they are saved in `~/Library/Application Support/Graffle/ShapeLibrary.json`, appear first in the list in every document, and can be renamed or deleted from their right-click menu.
- **Drafting (architectural plans):** the **Drafting** menu and two new dock tools turn Graffle into a precise 2D drafting board. **Drawing Scale…** says what a point stands for — measure in mm, cm, m, in or ft, as "1 point equals N" or a printed scale "1 : N" (at 72 points per inch), with decimals and wall thickness; without one a point is a centimeter. **Line (L)** and **Wall (W)** draw straight segments with a live length and angle bubble, **Ortho Mode** (⌥⌘O) locks them to right angles, **Shift** gives 15° steps, and **Object Snap** (⌃⌘E, Option to bypass) snaps to endpoints, midpoints, corners and centers, with a marker that names the point; walls are as thick as the scale says, with square ends so corners close. **Edit Dimension or Line…** (⌥⌘M) types an exact length and angle for a selected line. **Dimension lines** (⌥⌘1 horizontal, ⌥⌘2 vertical, ⌥⌘3 aligned) measure the selected shape (its width, height or length) or the gap between two; they read in the drawing's unit, follow the shapes when they move, take their own text if you type one, and export to PNG, PDF and SVG. **Arrange → Rotate** now turns a whole selection as one assembly. The Shape Library has an **Architecture** category of 29 real-size parts — single, double and sliding doors, windows, stairs, columns, beds, sofas, tables, kitchen and bathroom fixtures, north arrow — that are scaled to the drawing scale when placed (a door is 90 cm at any scale), and the **Floor Plan** starter shows it all at 1 point = 1 cm. Drawing is vector end to end; DXF/DWG import and export are not included.
- **STL to technical views:** *File → Import STL as Views…* reads a binary or ASCII STL and draws it as an engineering sheet in a new document: front, top, left and right side, bottom, back and an isometric view, as editable vector shapes. You choose the file's units (STL has none), the projection system — **European** (first angle: top view below the front, left profile to its right, as in Spanish-language drawing standards) or **American** (third angle) — which views to include, the crease angle that decides which mesh edges are drawn (so curved surfaces show their outline, not their triangles) and whether to show hidden lines as dashes (the isometric hides them by default). All views share one scale, each view is a named group with its title, and the front and side views get overall dimensions that read in the file's unit. Hidden lines come from a depth buffer, so very dense meshes take a few seconds.
- **Entity-relationship diagrams from a database:** after you pick the theme for an *Entity-Relationship Diagram*, a wizard opens. **Step 1** chooses the kind of database and how to connect: **SQLite** (a file), **PostgreSQL**, **MySQL / MariaDB**, **SQL Server**, or a **SQL script** (`.sql`, read without any server). **Step 2** lists the tables (with column and foreign-key counts, a filter, *Select All / None* and *Add Related*, which also ticks the tables the ticked ones refer to) and *Create Diagram* draws the ticked ones: a box per table with its columns (`PK`/`FK` marked, up to 18 shown) and a crow's-foot line for every foreign key between the ticked tables (zero-or-many when the key column is nullable, one-or-many when it isn't). **Cancel** at any point keeps the example tables the diagram normally starts with. Graffle only reads names and keys and never changes the database; the password is used for that connection only and is never saved (the other fields are remembered). SQLite and scripts need nothing else; the servers are reached through their command-line clients (`psql`, `mysql`, `sqlcmd`), which must be installed (the wizard says so, with a Homebrew hint). The password is passed to the client through its environment, not on the command line. Up to 60 tables per diagram; reading is approximate for exotic schemas (composite keys are drawn per column).
- **Class diagrams from code:** *File → New… → Classes Diagram* (or *File → Import Class Diagram…*) reads the **Swift, C#, Kotlin and Java** source files under a project (Xcode project or workspace, Swift package, .NET solution, Android/Gradle build, or any folder; `build`, `Pods`, `bin`, `obj`, `.build` and similar folders are skipped) and draws one UML-style box per class, struct, enum, protocol/interface, actor, object or record: its kind, name and supertypes, then its properties and methods with visibility marks (`+` public, `-` private, `#` protected, `~` internal). Extensions add their members, and enum cases are listed. Relationships are drawn between the types it finds: a **hollow arrow** for *extends*, a **dashed hollow arrow** for *implements/conforms*, and an **open arrow** when a property has another type of the project (that pair isn't also related by inheritance). Supertypes sit above the types that extend them. In the open panel you choose whether to show members, include test types and include private members; very large projects are cut to the 150 most connected types (the diagram says so). It reads text rather than compiling, so it is approximate: nested generics, unusual formatting and members declared by macros or code generators can be missed or simplified. Everything is an ordinary editable drawing and takes any theme.
- **New Document window and themes:** *File → New…* (⌘N) opens a two-step wizard in one window. **Step 1** is a gallery, like the template picker of a word processor, of what to start: **Blank Diagram**, **Software Architecture Diagram** and **Classes Diagram** (each with a picture of the kind of diagram it makes). **Step 2** shows the **themes**, each drawn on a sample of the diagram you chose, with *Back* to change your mind. *Create* then opens a blank document, or asks for the project to reverse engineer (and what to include) for the other two. The app starts with this window when nothing is open, and *File → New Blank Diagram* (⌥⌘N) skips it. *View → Theme…* opens the same gallery for the open diagram: it restyles every shape and connector in one undo step and is used for what you draw next. Each shape keeps its own color — themes derive their look from it (a pale fill with a strong outline counts as that outline's color) — so a color-coded diagram stays color-coded and switching themes never loses anything. The theme is saved inside the `.graf` file, so the diagram looks the same on a Mac that doesn't have it.
  Built in: *Clean*, *Soft UI*, *Frost* (frosted glass), *Midnight*, *Neumorphic Violet*, *Aurora Glass*, *Sky Wireframe*, *Soft Blue*, *Marker Doodle* (hatched marker scribbles), *Chalkboard* (chalk on dark slabs), *Green Chalk*, *HUD Neon*, *Cyber Cyan* and *Clay* (soft 3D). They can draw hand-drawn lines, hatching, glass, neumorphic and soft-3D shading, glows and soft shadows. A theme never recolors the canvas page (it stays white); the most it does is recolor the **grid** (HUD Neon, Cyber Cyan, Green Chalk and Marker Doodle do), so the grid contrasts with its shapes. PNG, PDF and Quick Look show all of it; SVG keeps colors, gradients and shadows but draws hand-drawn lines smooth and leaves out the glass/neumorphic/clay shading.
- **Theme files (`.graftheme`):** themes are plain JSON, and the built-in ones use the same format. *File → Import Theme…* (or **Import Theme…** in the New Document window) checks a file, explains any problem in plain words, and copies it to `~/Library/Application Support/Graffle/Themes`; it then appears in the gallery. An id that belongs to a built-in theme is refused; importing the same id again replaces the earlier copy. A starting point is in [`Examples/Ocean.graftheme`](Examples/Ocean.graftheme). The format (every field but `id` and `name` is optional; colors are `#RRGGBB` or `#RRGGBBAA`):
  - `format` (1), `id` (lowercase letters, digits, `-` `_` `.`), `name`, `author`, `summary`
  - `gridColor`: the canvas grid's color (`#RRGGBBAA`, the alpha sets how faint it is); leave it out for the usual faint black. The page itself is not themable. (An old `page` section in a file is ignored.)
  - `accent` and `accentMix` (0–1): pull every shape's color toward one hue
  - `shape`: `fill {mode: solid|gradient|none, surface, tint, lighten, darken, alpha, angle}`, `stroke {visible, color, lighten, darken, alpha, width, rough, cap, dash}`, `shadow {color, blur, offset, angle}`, `effect` (`neumorphic`, `crystal`, `glass`, `hatch`, `clay`), `cornerRadius`, `opacity`, `text {color, fonts[], bold}`
  - `connector`: `color`, `width`, `rough`, `cap`, `dash`, `glow`, `textColor`
  A visual theme editor is planned for a later release; for now themes are written by hand.
- **Interface (light and dark):** the window is a unified toolbar (sidebar toggle, document title menu with Rename/Duplicate/Move To…/Revert/Versions, undo, redo, export, and a **Share** button that opens the export menu) over three rounded cards: a **sidebar** (search, the page, and a **layers tree** whose child rows are each layer's objects: click to select on the canvas and the reverse, ⇧/⌘-click for several, drag layers or objects to reorder, double-click to rename, eye and lock buttons, a "N objects · N selected" footer), the **canvas** (dotted grid; rulers hidden until ⌘R) and the **inspector**. The tools float in a **dock** at the bottom of the canvas (Select V, Pan H, Zoom Z · Rectangle R, Rounded U, Ellipse O, Diamond D, Triangle Y · Text T, Connector C, Pen P · Line L, Wall W), with the **minimap and zoom pill** at the bottom right (click the percentage to fit). Selecting a shape shows a **contextual toolbar** above it (fill, stroke, edit text, add connector, duplicate, more), round corner handles and pill edge handles on an outline that follows the corner radius, and a size badge. The inspector has **Style / Arrange / Text** tabs, a header with the selection's editable name, **Geometry** (X, Y, W, H with arrow-key nudge, ⇧ for ×10 and drag-to-scrub on the label; "Mixed" for differing values), style presets, **Fill and Stroke** (swatch, hex field, color presets in a popover), opacity and shadow, **Arrange** (align, distribute, same size, order, move to layer) and a pinned **Export** card. *View → Appearance* chooses **System** (follows macOS live), **Light** or **Dark**; the canvas stays light in both so diagrams look the same when printed or exported. At narrow window widths the sidebar folds away by itself. Every colour, radius and size lives in one token file (`Sources/Graffle/UI/Tokens.swift`).
- **Shapes:** rectangle, rounded rectangle, ellipse, diamond, triangle and free text.
- **Fill:** none, solid color, linear gradient (with an angle) and radial gradient, with **any number of color stops**. In the gradient editor: click the bar to add a stop, drag a marker to move it (Shift = 5% steps), Delete removes it, and there are controls for color, position and reverse.
- **Line:** color, width, pattern (solid, dashed, long dash, dotted, dash-dot), cap (butt/round/square) and corner join (miter/round/bevel).
- **Shadow** with color, angle, blur and distance; **opacity** — the Fill section has an *Opacity* slider for the fill alone (solid color or every gradient stop, so the outline and text stay solid), and the Object section's *Overall* slider fades the whole object; **corner radius**.
- **Text:** font, size, bold, italic, underline, horizontal and vertical alignment, color (or automatic, chosen for contrast with the fill).
- **Connectors** attached to shapes: straight, curved, orthogonal and rounded orthogonal; 9 arrowhead types (arrow, open arrow, hollow triangle, diamond, circle, bar…) independent at each end, with adjustable size and a label.
- **Layers:** create, delete, reorder, rename, show/hide and lock; an active layer for new objects; move the selection to another layer. Hidden layers are also left out of exports.
- **Rotation** with the round handle above a shape (Shift = 15° steps) or with the Rotation dial in the inspector. The inspector's angles (rotation, shadow, linear gradient) are round dials: drag the needle (Shift = 15° steps) or type the value in the field. Connectors, shadows and resizing respect the angle.
- **Groups:** ⌘G groups the selection, ⇧⌘G ungroups it. One click selects the whole group and it moves together; copy/paste creates a new group.
- Multiple selection, move, resize with handles, arrow keys (Shift = 10 pt), grid with snapping.
- Undo/redo (continuous changes from sliders and color panels are merged into a single step), cut/copy/paste, duplicate, bring to front / send to back, align.
- **Distribute with equal spacing** (Arrange → Distribute Horizontally / Vertically, or the context menu): with three or more shapes, the outermost stay where they are and the ones in between are spread so the gaps are equal. Locked shapes don't move.
- **Match sizes** (Arrange → Same Width / Same Height / Same Size): every selected shape takes the width, height or both of the **first one you selected** (with a marquee selection or Select All, the rearmost one). Each keeps its top-left corner; locked shapes are unchanged.
- **Smart guides** (when moving, resizing and creating shapes): the edges and center of what you drag snap (within 6 pt) to those of the other shapes, and a magenta guide line appears while they are aligned; edge-to-edge snapping works too.
  - *When moving:* with several shapes selected they move as one box.
  - *When resizing:* the edge you drag snaps (one shape, or several at once as a group). Rotated shapes don't snap, because their edges don't follow the axes.
  - *When creating:* both the corner where you start and the one you drag snap.
  - **Equal-spacing guides (when moving):** if the shape ends up at the same distance from its two neighbors, or at the same distance that already exists between two other shapes in the same row or column, it snaps and brackets showing the size of the gap (e.g. "85") are drawn over all the equal gaps. Only shapes in the same row (for horizontal spacing) or column (vertical) count.
  Turn them off in View → Smart Guides (remembered) or by holding Option while dragging.
- **Copy and paste style** (Edit → Copy Style ⌥⌘C / Paste Style ⌥⌘V, and in the context menu): carries the whole look (fill, line, shadow, opacity, corners, text format) from one object to others, but not its geometry or its text. It works on several objects at once, also on locked objects, and is a single undo step. Fill and corners only travel between shapes: pasting a connector's style doesn't erase a shape's fill, and a connector never receives a fill. With nothing selected, "Paste Style" sets the look of new objects.
- **Palette of reusable styles** (the *Styles* section of the inspector): thumbnails that show the real look (gradient, shadow, dashed line, or "Aa" for text-only styles). One click applies the style to the selection (or to new objects when nothing is selected); the **+** button saves the selected object's style under the name you choose; right-click a thumbnail: Apply, Rename…, Update from Selection and Delete. The palette is stored in the app's preferences and works for every document; the first time it comes with seven starter styles (if you later delete them all, they don't come back).
- **Fonts:** the font picker lists every font family installed on the computer (each name in its own typeface). If a document uses a font that isn't installed, it is marked "(not installed)" instead of silently showing another one.
- **Context menu (right-click):** on an object it selects it (with its whole group, if it has one) and offers Cut, Copy, Paste, Duplicate, Delete, **Group / Ungroup**, **Lock / Unlock** (and Unlock All), Bring to Front, Send to Back, Move to Layer ▸, Align ▸ and Edit Text / Edit Points / Edit Label depending on the object. On empty canvas it offers Paste, Select All and Unlock All. The same commands are in the Edit and Arrange menus (Lock ⌘L, Unlock ⌥⌘L, Group ⌘G, Ungroup ⇧⌘G).
- **Per-object locking:** a locked object stays visible and can be selected (so you can unlock it) and restyled, but it can't be moved, resized, rotated, deleted, aligned or have its text or points edited, and it shows no handles; a padlock marks it. Pasting or duplicating creates unlocked copies. It is independent of layer locking.
- **Color presets in Fill:** six large grays and six hues (2 × 2 shades, from saturated to pale). With a solid fill they apply the color; with a gradient, to the selected stop. The one that matches the current color is highlighted.
- **Pen (`P`) for Bézier curves:** click = corner point; click and drag = smooth point with symmetric handles. Close the path by clicking the first point (it grows as you approach) and finish with Return, double-click or Esc; Delete removes the last point. Switching tools keeps what you drew. The result is a *path* shape (it rotates, resizes, exports to SVG and is saved like any other).
  **Point editing:** double-click a path (or press Return with the path selected) to show its anchors. Dragging an anchor moves it along with its handles; dragging a handle reshapes the curve (on a smooth point the opposite handle stays aligned; Option releases it); double-clicking an anchor toggles smooth/corner; double-clicking the line adds a point without changing the curve; Delete removes the selected point; Esc exits. Every change is an undo step. Paths with several subpaths (from an imported SVG) can't be edited point by point.
- **Resize several shapes as one unit:** with two or more shapes selected (or a group), a box with 8 handles appears and scales everything together. Shift on a corner keeps the proportions. Shapes rotated by 90° swap the axis that scales their size; at other angles they scale evenly, because a rotated shape can't be skewed.
- **Zoom and Navigator:** zoom from 10% to 800% with a pinch, ⌘ + scroll wheel (around the pointer), ⌘+ / ⌘-, ⌘0 (100%), ⌥⌘0 (*Zoom to Fit* the whole diagram) and ⌃⌘0 (*Zoom to Selection*), or with the **Zoom tool** (`Z`): click to zoom in, Option-click to zoom out, drag a box to zoom to that area. The **Navigator** (View → Show/Hide Navigator, ⌥⌘J; on by default) is the first section of the right sidebar, above Styles, like the Navigator in Photoshop: a live map of the whole diagram with a red box for the part that is on screen. Click or drag the map to scroll there, move the slider (or click the small/large rectangle at its ends) to zoom around the center of the view, type an exact percentage, or press *Fit*. Each window has its own; View hides or shows it in all of them, and its header collapses it.
- **Rulers** in points (View → Show Rulers, ⌘R, remembered between sessions), save/open (`.graf`, readable JSON) and export to PNG, PDF and **SVG** (⌥⌘E).
  The SVG keeps multi-stop gradients, line patterns, shadows, rotation, text with line breaks, connectors with arrowheads and labels, and every visible layer as a `<g>`; hidden layers are not exported.
- **SVG import:** *File → Open…* opens an `.svg` as a new document, and *Import SVG…* (⇧⌘I) adds it to the current document as a new layer, grouped, near the visible corner of the canvas (a single undo step).
  It reads `rect` (with rounded corners), `circle`, `ellipse`, `line`, `polyline`, `polygon`, `path` (M L H V C S Q T A Z, absolute and relative), `text`/`tspan`, nested groups with transforms, `viewBox`, `fill`/`stroke` by attribute or `style=""`, linear and radial gradients with any number of stops, dash patterns, opacity and shadows (`feDropShadow`). Diamonds and triangles are recognized as native shapes; rectangles, ellipses and text keep their rotation. Lines and curves become *path* shapes: you can select them by clicking on the stroke, and move, rotate and resize them.
  Limitations: images, `<use>`, patterns, `clipPath`, masks, `<style>` blocks (CSS) and filters other than a shadow are skipped, and you are told how many; dashes use the closest preset pattern; text arrives as loose text boxes (not inside the shape); connectors from an SVG exported by the app come back as strokes not attached to the shapes.

- **Generate code (empty folder only):** documents created as **Software Architecture**, **Classes** or **Entity-Relationship** keep the model they came from, and *File → Generate Code…* (⌥⇧⌘G) turns it into files. It is disabled for any other document.
  Classes → one file per type in **Swift, C#, Kotlin or Java** (plus `Package.swift` / `.csproj` / Gradle files), with `TODO` bodies; Entity-Relationship → a `schema.sql` for **PostgreSQL, MySQL, SQLite or SQL Server** (tables in dependency order, keys, foreign keys, identity columns); Software Architecture → an empty **Swift package, .NET solution or Gradle multi-module** project with one module per target, wired by its dependencies (external packages are listed in the README to add by hand).
  The folder must be **empty** (`.DS_Store` is ignored; you can create one in the panel): otherwise nothing is written and you are told what is in the way. Files are never overwritten, paths can't leave the folder, and if a write fails everything written is removed. Limitation: the code comes from the model as it was created or imported, not from later edits to the shapes, and method parameter types are not kept in class diagrams (they appear as `Any`/`object`).

The inspector on the right is a single column of collapsible sections (**Fill, Line, Shadow, Object, Text, Connector**) with the **Layers** panel always visible at the bottom. Only what the selection needs is shown: **Text** with shapes or connectors selected (connectors carry a label), **Connector** only with connectors, and **Fill** is hidden when only connectors are selected. With nothing selected, changes define how new objects are created. The menus for line pattern, cap, join, connector type, arrowheads, fill type and text alignment show drawings instead of words (the name appears as a tooltip), and the font list shows each name in its own typeface. The **Shadow** controls appear only while the shadow is on. Each slider has a field to its right where you can type the exact value (clamped to the range; opacity is typed as %), and all the drop-downs are the same width.

## Development tests

To follow the Quick Look extension while previewing a file: `qlmanage -p some.graf`, then `/usr/bin/log show --last 2m --info --predicate 'subsystem == "mx.graffle.app.quicklook"'` (use `/usr/bin/log`: in zsh, plain `log` is a different command). `pluginkit -m -p com.apple.quicklook.preview -vv | grep -i graffle` shows whether macOS has registered it.

```bash
.build/debug/Graffle --selftest                    # simulates mouse/keyboard on the canvas
build/Graffle.app/Contents/MacOS/Graffle --selftest  # the same, plus the multi-document tests (they need the .app's Info.plist)
.build/debug/Graffle --render-sample out.png       # renders a sample diagram (also .svg, .selected.png, ...)
```
